💡 Conceito
📦 Módulos

Cada arquivo .py é um módulo. Você escolhe o que importar:

  • import modulo — traz o módulo inteiro; acessa com modulo.Classe()
  • from modulo import Classe — traz só a classe; acessa direto
  • from modulo import Classe as C — apelido para evitar conflito de nomes
⚠ Evite isso

from database import * traz tudo para o namespace e pode sobrescrever nomes que você já tinha. Difícil rastrear de onde cada nome veio.

📝 Docstrings (PEP 257)

Uma docstring é uma string logo abaixo de def ou class. Ela fica acessível em __doc__ e aparece no help(). Use Args: e Returns: para documentar parâmetros.

🌍 No mundo real

Execute: python -c "import rich; help(rich)" — você verá as docstrings dos desenvolvedores da biblioteca. É exatamente isso que você vai produzir.

Métodos dunder em Ponto

ponto.py 
class Ponto:
    def __init__(self, x, y):
        self.x = x; self.y = y

    def __str__(self):
        return f"Ponto({self.x}, {self.y})"     # legível

    def __repr__(self):
        return f"Ponto(x={self.x}, y={self.y})"  # técnico

    def __add__(self, outro):
        return Ponto(self.x + outro.x, self.y + outro.y)

p1, p2 = Ponto(1,2), Ponto(3,4)
print(p1)         # → "Ponto(1, 2)"
print(p1 + p2)    # → "Ponto(4, 6)"

💡 Conceito
🧬 Herança

Uma subclasse recebe automaticamente todos os atributos e métodos da superclasse. Cachorro herda de Animal — ele pode respirar() sem você reimplementar.

Terminologia: Animal = superclasse · Cachorro = subclasse · rex.respirar() = método herdado.

🔗 super()

Quando a subclasse precisa de seu próprio __init__ mas quer aproveitar o do pai, use super().__init__(...). Sem isso, os atributos do pai não são inicializados.

⚠ Erro comum — duplicação

Reescrever self.nome = nome dentro da subclasse. Use super().__init__(...) e evite duplicação e bugs de manutenção.

📌 Atributo de classe vs instância

bonus_racial = {} dentro da classe (fora de métodos) é compartilhado por todos os objetos. self.nome = nome é individual. Cuidado com mutação de atributos de classe!

🌍 No mundo real

unittest.TestCase herda de object mas adiciona assertEqual, assertRaises etc. pathlib.Path herda de PurePath adicionando operações de sistema de arquivos.

▶ Exemplo

Herança básica com super()

contato.py 
class Contato:
    def __init__(self, nome, email):
        self.nome = nome
        self.email = email

class Amigo(Contato):            # Amigo herda de Contato
    def __init__(self, nome, email, telefone):
        super().__init__(nome, email)   # executa __init__ do pai
        self.telefone = telefone         # adiciona o que é próprio
🎁 Bônus — Inventario(list) — herança de built-in

Você pode herdar de tipos built-in do Python, como list. A classe filha ganha append, sort, len de graça e adiciona seus próprios métodos:

inventario.py 
class Inventario(list):     # herda de list!
    def buscar(self, nome):
        return [c for c in self if nome in c.nome]

# Inventario tem TUDO de list: append, sort, len...
inv = Inventario()
inv.append(heroi1)       # método herdado
inv.buscar("Arador")    # método próprio

💡 Conceito
🎭 Polimorfismo

Mesma chamada, comportamentos diferentes dependendo do tipo real do objeto. O laço for audio in arquivos: audio.play() funciona para MP3, WAV, OGG — Python decide qual play() chamar.

Sem polimorfismo: if type(audio) == MP3: ... elif type(audio) == WAV: ... — teria que atualizar toda vez que adicionasse um novo tipo.

🚫 Método "abstrato" simulado

Levantando NotImplementedError na superclasse, você força as subclasses a implementar o método. Tentar chamar em um objeto base gera erro intencional e claro.

⚠ Erro esperado (intencional!)

Se a subclasse não sobrescreve atacar() e a superclasse levanta NotImplementedError, chamar p.atacar(alvo) vai falhar. Isso é correto — você deve implementar nas subclasses.

🌍 No mundo real

O módulo abc (Abstract Base Classes) da biblioteca padrão fornece uma forma formal de métodos abstratos via @abstractmethod. O padrão NotImplementedError é igualmente válido e amplamente usado.

"""Arena — orquestra batalhas polimorficamente (arquivo já pronto)."""

import random
from personagem import Personagem
from rich.console import Console
from rich.table import Table


class Arena:
    def __init__(self, personagens: list):
        self.personagens = personagens
        self.historico = []

    def batalhar(self, rodadas: int = 3) -> None:
        console = Console()
        for rodada in range(1, rodadas + 1):
            console.rule(f"[bold yellow]Rodada {rodada}[/bold yellow]")
            for atacante in self.personagens:
                if not atacante.esta_vivo():
                    continue
                vivos = [p for p in self.personagens
                         if p.esta_vivo() and p is not atacante]
                if not vivos:
                    break
                alvo = random.choice(vivos)
                dano = atacante.atacar(alvo)   # ← polimorfismo aqui!
                self.historico.append(
                    f"R{rodada}: {atacante.nome} → {alvo.nome} ({dano})")
            vivos_nomes = [p.nome for p in self.personagens if p.esta_vivo()]
            console.print(f"  Vivos: {', '.join(vivos_nomes) or 'nenhum'}")

    def relatorio_rich(self) -> None:
        console = Console()
        t = Table(title="Resultado Final")
        t.add_column("Personagem"); t.add_column("Raça")
        t.add_column("PV", justify="right"); t.add_column("Status")
        for p in self.personagens:
            status = "[green]Vivo[/green]" if p.esta_vivo() else "[red]Derrotado[/red]"
            t.add_row(p.nome, type(p).__name__, str(p.pontos_de_vida), status)
        console.print(t)
