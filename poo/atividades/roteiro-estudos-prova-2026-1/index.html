🎯 Como estudar

  1. Refaça a revisão das aulas 5-6. A prova segue o mesmo estilo da atividade da gincana — quem domina aquela atividade está com ~60% do caminho andado.
  2. Execute código de verdade. Digite os exemplos no computador, PREVEJA a saída antes de rodar e confira. Errou? Descubra por quê. Esse ciclo vale mais que reler slides.
  3. Desenhe o UML do seu projeto final. Use o diagrama do seu grupo para treinar visibilidade, relacionamentos e multiplicidade.
  4. Estude em grupo, responda sozinho. Explicar um conceito para o colega é o melhor teste de que você sabe.

📚 O que cai, aula por aula

🧱 Aula 1 — Conceitos básicos ▶
  • Classe × objeto/instância · atributo × método · construtor __init__ · o papel do self
  • Atributo de classe (compartilhado) × atributo de instância (de cada objeto)
🔒 Aula 2 — Encapsulamento ▶
  • Visibilidade: público, _protegido (convenção), __privado (name mangling → _Classe__attr)
  • @property e setter com validação — por que é melhor que atributo público
🧩 Aula 3 — Módulos, docstrings e sobrecarga ▶
  • from modulo import Nome × import modulo · docstrings ("""...""", help(), __doc__)
  • Métodos especiais: __str__ (o que o print mostra), __eq__ (sem ele, == compara identidade!), __add__, __lt__
🧬 Aula 4 — Herança e polimorfismo ▶
  • class Filha(Mae) · super().__init__(...) · sobrescrita de métodos
  • Polimorfismo: o mesmo bicho.falar() com comportamentos diferentes no loop
  • Herança é "é um" · composição é "tem um" — Motor NÃO herda de Carro!
🦆 Aula 5 — POO avançada ▶
  • Duck typing: importa o comportamento, não a linhagem — erro só aparece na chamada
  • ABC: contrato explícito; instanciar com @abstractmethod pendente → TypeError na hora
  • Interfaces · mixins · MRO: D(B, C) procura em D → B → C → A
📐 Aulas 6 e 6-2 — UML ▶
  • Classe em 3 compartimentos (nome, atributos, métodos) · visibilidade + − #
  • Os 5 relacionamentos: herança (triângulo vazado, linha contínua) · realização (triângulo vazado, tracejada) · dependência (seta aberta tracejada) · associação (linha contínua) · agregação (losango vazio) × composição (losango preenchido)
  • Multiplicidade: 1, 0..1, 0..*, 1..*
  • Diagrama ↔ código: cria a parte dentro do todo = composição · recebe pronta = agregação · usa só como parâmetro = dependência
